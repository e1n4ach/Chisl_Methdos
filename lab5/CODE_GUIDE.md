## Строки 37–43. Функции левого и правого ГУ

```python
    def left(self, t):
        rate = self.c - self.a if self.left_rate is None else self.left_rate
        return self.left_amplitude * np.exp(rate * t)

    def right(self, t):
        rate = self.c - self.a if self.right_rate is None else self.right_rate
        return self.right_amplitude * np.exp(rate * t)
```

- **37.** `left(self, t)` объявляет функцию $\varphi(t)$ — правую часть левого ГУ. Это не функция самого $u(0,t)$: слева в условии стоит комбинация производной и значения.
- **38.** Условное выражение `A if условие else B` выбирает `self.c-self.a`, если `left_rate is None`; иначе берёт явно заданный `left_rate`. Проверка `is None` проверяет отсутствие настройки. Полученный показатель сохраняется в локальную переменную `rate`.
- **39.** Возвращается $\varphi(t)=A_L e^{r_Lt}$, где $A_L$ — `left_amplitude`, $r_L$ — `rate`. `np.exp` вычисляет экспоненту для числа или массива `t`.
- **40.** Пустая строка отделяет методы.
- **41.** `right(self, t)` объявляет функцию $\psi(t)$ — известное значение $u(\ell,t)$.
- **42.** Показатель правой экспоненты выбирается независимо: по умолчанию `c-a`, иначе `right_rate`.
- **43.** Возвращается $\psi(t)=A_R e^{r_Rt}$. При стандартных параметрах обе функции ГУ равны $e^{(c-a)t}$, но смысл у них разный: слева задаётся производная, справа — значение решения.

## Строки 45–46. Аналитическое решение

```python
    def exact(self, x, t):
        return np.exp((self.c - self.a) * t) * np.sin(x)
```

- **45.** `exact(self, x, t)` объявляет метод известного аналитического решения. Он используется для сравнения, а не для вычисления внутренних узлов численного решения.
- **46.** Возвращается $U(x,t)=e^{(c-a)t}\sin x$. Умножение выполняется поэлементно, с согласованием форм массивов NumPy.

Проверка формулы: $U_t=(c-a)U$, а $U_{xx}=-U$, поэтому $aU_{xx}+cU=(c-a)U=U_t$.
При $t=0$ получается $\sin x$. Производная $U_x=e^{(c-a)t}\cos x$, следовательно,
$U_x(0,t)=e^{(c-a)t}$; при $\ell=\pi/2$ имеем $U(\ell,t)=e^{(c-a)t}$.
Именно эти равенства связывают формулу с вариантом 8.

## Строки 48–53. Проверка применимости аналитического решения

```python
    def has_exact(self):
        """При независимом изменении ГУ прежнее U может перестать быть решением."""
        return (np.isclose(self.left_amplitude, self.alpha)
                and np.isclose(self.right_amplitude, np.sin(self.length))
                and (self.left_rate is None or np.isclose(self.left_rate, self.c-self.a))
                and (self.right_rate is None or np.isclose(self.right_rate, self.c-self.a)))
```

- **48.** `has_exact(self)` объявляет метод, возвращающий логическое значение: согласованы ли заданные функции ГУ с написанной выше формулой `exact`.
- **49.** Docstring объясняет причину проверки: при независимом изменении ГУ прежняя аналитическая формула может стать неверной.
- **50.** Начинается составное условие `return (...)`. `np.isclose` проверяет приближённое равенство `left_amplitude` и `alpha`. Для $U$ слева $U(0,t)=0$, $U_x(0,t)=e^{(c-a)t}$, значит $\alpha U_x+\beta U=\alpha e^{(c-a)t}$. Поэтому требуемая амплитуда равна $\alpha$, независимо от $\beta$.
- **51.** `and` требует также `right_amplitude ≈ sin(length)`, поскольку $U(\ell,t)=\sin\ell\,e^{(c-a)t}$.
- **52.** Ещё одно `and` проверяет левый показатель: либо настройка не задана (`None`, и тогда автоматически берётся `c-a`), либо она близка к `c-a`. `or` внутри скобок означает «достаточно одного из двух условий».
- **53.** Аналогично проверяется правый показатель. Закрываются вложенные скобки и весь `return`. Результат — истина только при выполнении всех четырёх групп условий.

Здесь `np.isclose` использует стандартные допуски NumPy, поэтому речь о численной проверке,
а не о символьном доказательстве. Метод проверяет именно параметры ГУ; если вручную изменить
`source`, `initial` или `exact`, сам по себе он эти изменения не проанализирует.

## Строки 56–61. boundary_relation: двухточечное ГУ первого порядка

```python
def boundary_relation(problem, h, boundary):
    """Алгебраическое ГУ: u0 = k1*u1 + k2*u2 + g*left(t)."""
    alpha, beta = problem.alpha, problem.beta
    if boundary == "first":
        denominator = beta - alpha / h
        coefficients = (-alpha / h, 0.0, 1.0)
```

- **56.** Объявляется обычная функция `boundary_relation`, уже вне класса. `problem` — объект задачи; `h` — пространственный шаг; `boundary` — имя аппроксимации.
- **57.** Docstring задаёт форму результата: $u_0=k_1u_1+k_2u_2+g\varphi(t)$. Здесь $g$ — **скалярный коэффициент** при левой граничной функции, не весь вектор внешнего воздействия.
- **58.** Распаковка двух значений создаёт короткие локальные имена `alpha`, `beta` из полей объекта.
- **59.** Если выбрано `first`, выполняется ветка двухточечной направленной разности.
- **60.** В `denominator` сохраняется знаменатель $D_1=\beta-\alpha/h$.
- **61.** `coefficients` — кортеж трёх числителей: $(-\alpha/h,0,1)$. Пока деления на $D_1$ нет; оно будет в конце функции.

Математический переход к этим коэффициентам:

$$
u_x(0,t)\approx\frac{u_1-u_0}{h},\qquad
\alpha\frac{u_1-u_0}{h}+\beta u_0=\varphi(t),
$$

$$
\left(\beta-\frac\alpha h\right)u_0
=-\frac\alpha h u_1+\varphi(t),\qquad
u_0=\frac{-\alpha/h}{D_1}u_1+0\,u_2+\frac1{D_1}\varphi(t).
$$

Именно числители последней формулы записаны в строке 61. При $\alpha=1$, $\beta=0$
получаем $u_0=u_1-h\varphi(t)$ — знак минус соответствует производной по направлению роста $x$.
Для гладкого решения $(U(h)-U(0))/h=U_x(0)+hU_{xx}(0)/2+O(h^2)$,
поэтому формула в общем случае первого порядка. В варианте 8 $U_{xx}(0,t)=0$,
и ведущая ошибка исчезает: наблюдаемый порядок может оказаться вторым.

## Строки 70–76. spatial_operator: сетка и состав неизвестных

```python
def spatial_operator(problem, n, boundary):
    """Три диагонали L и добавка g(t) в системе v_t = L*v + g(t)."""
    h = problem.length / n
    diffusion = problem.a / h**2
    start = 0 if boundary == "pde" else 1
    x = np.linspace(0, problem.length, n+1)
    size = n - start
```

- **70.** Функция строит пространственную часть задачи. `n` — число интервалов по пространству; узлов на один больше: $i=0,\ldots,n$.
- **71.** Docstring описывает результат как систему ОДУ $v_t=L v+g(t)$. Здесь $L$ — матрица пространственного оператора; $g(t)$ — **вектор**, содержащий источник и известные граничные значения. Название `L` обозначает матрицу, длина области хранится отдельно как `problem.length`.
- **72.** Вычисляется $h=\ell/n$. Все интервалы сетки одинаковы.
- **73.** `diffusion = a/h**2`: `**2` означает квадрат. Обозначим этот коэффициент $d=a/h^2$.
- **74.** `start` — индекс первого узла, входящего в вектор неизвестных $v$. Для `pde` это 0, для двух алгебраических ГУ — 1.
- **75.** `np.linspace(0, length, n+1)` создаёт координаты $x_i=ih$, включая 0 и $\ell$. Длина `x` равна `n+1`.
- **76.** `size=n-start` — длина $v$. Правый узел $u_n$ известен из ГУ и всегда исключён из неизвестных. Для `first`/`three` вектор $v=(u_1,\ldots,u_{n-1})$ имеет `n-1` элементов; для `pde` $v=(u_0,\ldots,u_{n-1})$ имеет `n` элементов.

Пример при `n=4`: физические узлы имеют индексы `0,1,2,3,4`.
Для `first`/`three` строки матрицы относятся к `u1,u2,u3`; для `pde` — к `u0,u1,u2,u3`.
Поэтому индекс строки матрицы и индекс физического узла могут отличаться на 1:
$j=i-\texttt{start}$. Ниже `diagonal[0]` всегда относится к первому элементу **вектора неизвестных**.

## Строки 77–79. Три диагонали пространственной матрицы

```python
    lower = np.full(size-1, diffusion)
    diagonal = np.full(size, -2*diffusion + problem.c)
    upper = np.full(size-1, diffusion)
```

- **77.** `np.full(size-1, diffusion)` создаёт нижнюю диагональ: `size-1` одинаковых значений $d$. Элемент `lower[j]` расположен в матрице в строке `j+1`, столбце `j`.
- **78.** `diagonal` содержит `size` элементов главной диагонали $-2d+c$, по одному на каждую неизвестную.
- **79.** `upper` — верхняя диагональ длины `size-1`; `upper[j]` расположен в строке `j`, столбце `j+1`. Начальные значения также равны $d$.

Для внутреннего узла центральная разность даёт

$$
\frac{du_i}{dt}
=a\frac{u_{i-1}-2u_i+u_{i+1}}{h^2}+cu_i+f_i(t)
=d u_{i-1}+(-2d+c)u_i+d u_{i+1}+f_i(t).
$$

Поэтому в обычной строке матрицы только три ненулевых коэффициента.
При трёх неизвестных схема хранения соответствует матрице
$\begin{pmatrix}b_0&r_0&0\\l_0&b_1&r_1\\0&l_1&b_2\end{pmatrix}$,
где `diagonal=[b0,b1,b2]`, `lower=[l0,l1]`, `upper=[r0,r1]`.

## Строки 80–84. Двухточечное ГУ второго порядка через уравнение

```python
    if boundary == "pde":
        # u1 = u0 + h*ux + h²/(2a)*(ut-c*u0-f) + O(h³).
        # Исключаем ux=(left-beta*u0)/alpha и выражаем ut в узле 0.
        diagonal[0] += 2*problem.a*problem.beta/(problem.alpha*h)
        upper[0] = 2*diffusion
```

- **80.** Эта ветка выполняется только для `boundary == "pde"`. В этом случае $u_0$ входит в вектор неизвестных.
- **81.** Комментарий записывает ряд Тейлора для $u_1=U(h,t)$ около нуля, уже с заменой $U_{xx}=(U_t-cU-f)/a$ из уравнения. $O(h^3)$ — остаток ряда до деления на $h$ или $h^2$.
- **82.** Второй комментарий поясняет замену $U_x=(\varphi-\beta U_0)/\alpha$ из левого ГУ. Затем из полученного равенства выражается $U_t$.
- **83.** `+=` прибавляет к уже имеющемуся `-2d+c` коэффициент $2a\beta/(\alpha h)$. Это коэффициент при $u_0$ в граничной строке.
- **84.** Коэффициент при $u_1$ становится $2d$. Здесь именно присваивание `=`, потому что стандартное значение $d$ заменяется на $2d$.

Полный переход от математических условий к коду:

$$
U_1=U_0+hU_x(0,t)+\frac{h^2}{2}U_{xx}(0,t)+O(h^3),
$$

$$
U_1-U_0=\frac h\alpha(\varphi-\beta U_0)
+\frac{h^2}{2a}(U_t(0,t)-cU_0-f(0,t))+O(h^3).
$$

После переноса членов и умножения на $2a/h^2$ получается граничное уравнение:

$$
\frac{du_0}{dt}
=2d\,u_1+\left(-2d+c+\frac{2a\beta}{\alpha h}\right)u_0
-\frac{2a}{\alpha h}\varphi(t)+f(0,t).
$$

Два коэффициента при неизвестных записаны в `diagonal[0]` и `upper[0]`.
Известная часть с $\varphi$ будет записана в `forcing` ниже.
Используются только два пространственных узла $u_0,u_1$.

Почему это называют вторым порядком ГУ: если выразить **производную** из ряда,
то $U_x\approx(U_1-U_0)/h-h(U_t-cU_0-f)/(2a)$ с остатком $O(h^2)$.
При преобразовании в строку для $U_t$ остаток масштабируется и становится $O(h)$;
это не означает первый порядок глобальной ошибки решения. Порядок граничной формулы
и невязка строки после умножения на зависящий от $h$ множитель — разные величины.
Для этой задачи сходимость второго порядка проверяется сгущением сетки.
В варианте 8 $\beta=0$, $\alpha=1$, и строка упрощается до
$\dot u_0=2d(u_1-u_0)+cu_0-2a\varphi/h$.

## Строки 85–88. Исключение алгебраического левого ГУ из матрицы

```python
    else:
        k1, k2, _ = boundary_relation(problem, h, boundary)
        diagonal[0] += diffusion*k1
        upper[0] += diffusion*k2
```

- **85.** Ветка `else` обслуживает `first` и `three`: их $u_0$ не входит в $v$.
- **86.** Функция `boundary_relation` возвращает три коэффициента. Первые два сохраняются как `k1`, `k2`, третий записывается в `_`. Подчёркивание — обычное имя переменной, принятое здесь как указание «это значение пока не нужно».
- **87.** В первую главную диагональ добавляется $dk_1$: `diagonal[0]` теперь коэффициент при $u_1$, поскольку первая неизвестная — $u_1$.
- **88.** В первую верхнюю диагональ добавляется $dk_2$: это поправка к коэффициенту при $u_2$. Для `first` $k_2=0$, поэтому поправка нулевая.

Внутреннее уравнение для $u_1$ изначально содержит неизвестное $u_0$:

$$
\dot u_1=d u_0+(-2d+c)u_1+d u_2+f_1.
$$

Подставим $u_0=k_1u_1+k_2u_2+g\varphi$:

$$
\dot u_1=(-2d+c+dk_1)u_1+(d+dk_2)u_2+dg\varphi(t)+f_1.
$$

Эта формула даёт обе строки обновления диагоналей. В отличие от хранения отдельного
трёхточечного граничного уравнения, после исключения $u_0$ матрица по оставшимся
неизвестным остаётся трёхдиагональной даже для `three`.

## Строки 90–99. forcing: источник и известные граничные значения

```python
    def forcing(t):
        values = np.broadcast_to(problem.source(x[start:n], t), (size,)).copy()
        values[-1] += diffusion * problem.right(t)
        if boundary == "pde":
            values[0] -= 2*problem.a/(problem.alpha*h) * problem.left(t)
        else:
            values[0] += diffusion*boundary_relation(problem, h, boundary)[2]*problem.left(t)
        return values

    return lower, diagonal, upper, forcing
```

- **90.** `forcing(t)` — функция, определённая внутри `spatial_operator`. Она запоминает доступ к `problem`, `x`, `start`, `size`, `h`, `diffusion`, `boundary` из окружающей функции. Такое сохранение окружения называется замыканием. Результат — вектор известной добавки в момент `t`.
- **91.** `x[start:n]` выбирает координаты неизвестных: начало включается, правая граница среза `n` **не включается**. При `pde` это `x0,...,x[n-1]`, при остальных — `x1,...,x[n-1]`. `problem.source(..., t)` вычисляет $f$ в этих точках. `np.broadcast_to(..., (size,))` приводит результат к одномерной форме `(size,)`: например, общий скаляр источника повторяется для всех узлов. Запятая в `(size,)` делает это кортежем из одного элемента. `.copy()` создаёт отдельный изменяемый массив: результат `broadcast_to` обычно доступен только для чтения.
- **92.** `values[-1]` — последний элемент вектора, относящийся к узлу $u_{n-1}$. К нему добавляется $d\psi(t)$: это вклад известного правого узла $u_n=\psi(t)$ из центральной разности. Отрицательный индекс `-1` означает последний элемент, а не узел с физическим индексом минус один.
- **93.** Для `pde` выбирается известная часть граничной строки для $u_0$.
- **94.** `-=` вычитает $2a\varphi(t)/(\alpha h)$ из первой компоненты. Знак следует из выведенного выше граничного уравнения; источник $f(0,t)$ уже находится в `values[0]` после строки 91.
- **95.** `else` выбирает алгебраические способы обработки ГУ.
- **96.** Вызов `boundary_relation(...)[2]` берёт третий элемент результата: скаляр $g$. К первой компоненте вектора добавляется $d g\varphi(t)$, как получено при исключении $u_0$ из уравнения для $u_1$.
- **97.** `return values` возвращает готовый вектор внешней добавки для указанного времени.
- **98.** Пустая строка отделяет тело вложенной функции от следующего оператора внешней функции.
- **99.** Возвращаются три массива диагоналей и **сама функция** `forcing`. Без скобок после имени функция не вызывается. Поэтому вызывающий код сможет вычислять добавку для разных `t`, не перестраивая диагонали.

## Строки 102–106. apply_operator: умножение трёхдиагональной матрицы на вектор

```python
def apply_operator(lower, diagonal, upper, values):
    result = diagonal * values
    result[1:] += lower * values[:-1]
    result[:-1] += upper * values[1:]
    return result
```

- **102.** Объявляется функция вычисления $L v$. Здесь `values` — произвольный вектор неизвестных длины $m=\texttt{size}$; это другая локальная переменная, не массив из `forcing`.
- **103.** `diagonal * values` поэлементно вычисляет $b_jv_j$ для всех $j$. Получается новый массив `result` длины $m$, исходный `values` не меняется.
- **104.** `result[1:]` содержит позиции `1,...,m-1`; `values[:-1]` содержит `0,...,m-2`. Их длины равны `m-1`, как и длина `lower`. Поэтому к строке `j` прибавляется `lower[j-1]*values[j-1]`, то есть вклад левого соседа. Первая строка пропускается: нижней диагонали в ней нет.
- **105.** `result[:-1]` содержит позиции `0,...,m-2`; `values[1:]` — `1,...,m-1`. Добавляется вклад правого соседа `upper[j]*values[j+1]`. Последняя строка пропускается: верхней диагонали в ней нет.
- **106.** Возвращается сумма всех трёх вкладов, то есть вектор $Lv$.

Для трёх неизвестных результат равен

$$
\begin{pmatrix}
b_0v_0+r_0v_1\\
l_0v_0+b_1v_1+r_1v_2\\
l_1v_1+b_2v_2
\end{pmatrix}.
$$

Срез `a[p:q]` везде включает `p` и исключает `q`; пропущенное начало означает 0,
пропущенный конец — до конца. Здесь срезы позволяют обработать соседей сразу для всех строк,
не создавая полную квадратную матрицу. Символ `*` для NumPy-массивов — поэлементное
умножение; матричное умножение достигается именно суммированием трёх сдвинутых вкладов.

## Строки 109–112. factor_tridiagonal: подготовка прогонки

```python
def factor_tridiagonal(lower, diagonal, upper):
    """Прямая часть прогонки; матрица постоянна на всей временной сетке."""
    pivots = diagonal.copy()
    multipliers = lower.copy()
```

- **109.** Функция принимает три диагонали некоторой трёхдиагональной матрицы $A$ и готовит её исключение Гаусса без выбора главного элемента. Это первая часть метода прогонки.
- **110.** Docstring поясняет, почему работу можно выполнить один раз: при постоянных коэффициентах и постоянном шаге времени матрица всех временных шагов одинакова.
- **111.** `pivots=diagonal.copy()` копирует главную диагональ. В копии будут храниться изменённые ведущие коэффициенты $p_i$; оригинал не испортится.
- **112.** `multipliers=lower.copy()` копирует нижнюю диагональ. Позже каждый элемент заменится на множитель исключения $m_i$.

Пусть строки исходной системы имеют вид
$a_{i-1}z_{i-1}+b_i z_i+r_i z_{i+1}=d_i$ для внутренних строк.
Здесь $a_{i-1}=\texttt{lower[i-1]}$, $b_i=\texttt{diagonal[i]}$,
$r_i=\texttt{upper[i]}$; $z$ — искомое решение линейной системы.
Нумерация локальная, от 0 до $m-1$, и не обязана совпадать с физическими узлами $u_i$.

## Строки 113–120. factor_tridiagonal: исключение нижней диагонали

```python
    for i in range(1, len(pivots)):
        if abs(pivots[i-1]) < 1e-14:
            raise ValueError("Нулевой ведущий элемент прогонки.")
        multipliers[i-1] /= pivots[i-1]
        pivots[i] -= multipliers[i-1]*upper[i-1]
    if abs(pivots[-1]) < 1e-14:
        raise ValueError("Вырожденная матрица схемы.")
    return multipliers, pivots, upper
```

- **113.** `range(1, len(pivots))` перебирает `i=1,...,m-1`. Первая строка `i=0` уже задаёт $p_0=b_0$ и не требует исключения предыдущего элемента.
- **114.** Перед делением проверяется модуль предыдущего ведущего элемента `pivots[i-1]`.
- **115.** Если он меньше $10^{-14}$, выдаётся исключение: прогонка в таком виде не может надёжно делить на него.
- **116.** Операция `/=` заменяет `multipliers[i-1]` на $m_i=a_{i-1}/p_{i-1}$. До этой строки там хранился исходный нижний коэффициент $a_{i-1}$.
- **117.** Из главного коэффициента текущей строки вычитается множитель, умноженный на верхний коэффициент предыдущей строки: $p_i=b_i-m_i r_{i-1}$. Именно `upper[i-1]` расположен в предыдущей строке и том столбце, который сейчас становится диагональным.
- **118.** После цикла отдельно проверяется последний ведущий элемент `pivots[-1]`. Он не стал бы «предыдущим» на следующей итерации, потому что следующей итерации уже нет.
- **119.** При почти нулевом последнем элементе также выбрасывается `ValueError`. Это диагностическое сообщение; в общем случае матрица может требовать перестановок строк, которых эта реализация не делает.
- **120.** Возвращаются сохранённые множители, изменённая главная диагональ и неизменённая верхняя диагональ. Последняя возвращается без копирования, поскольку здесь её никто не меняет.

Вывод: после обработки предыдущей строки вычитаем из строки $i$ строку $i-1$,
умноженную на $m_i=a_{i-1}/p_{i-1}$. Коэффициент при $z_{i-1}$ становится
$a_{i-1}-m_i p_{i-1}=0$, а при $z_i$ остаётся $b_i-m_i r_{i-1}$.
Это и есть строки 116–117. Получена верхнетреугольная матрица.
Формально выполняется факторизация $A=\mathcal L\mathcal U$, где $\mathcal L$ имеет единицы
на главной диагонали и множители $m_i$ под ней, а $\mathcal U$ — диагональ `pivots` и наддиагональ `upper`.
Не следует путать матрицу $\mathcal L$ факторизации с пространственной матрицей $L$.
Все действия требуют $O(m)$ операций и памяти; правой части в этой функции ещё нет.

## Строки 123–128. solve_tridiagonal: прямая обработка правой части

```python
def solve_tridiagonal(factors, rhs):
    multipliers, pivots, upper = factors
    result = rhs.copy()
    for i in range(1, len(result)):
        result[i] -= multipliers[i-1]*result[i-1]
    result[-1] /= pivots[-1]
```

- **123.** Функция решает $Az=\texttt{rhs}$ по уже подготовленным данным `factors`. `rhs` означает right-hand side — правую часть системы.
- **124.** Тройка данных распаковывается в `multipliers`, `pivots`, `upper` в том же порядке, в каком была возвращена факторизацией.
- **125.** Создаётся копия правой части, чтобы её преобразования не изменили исходный `rhs`. В этом же массиве затем будет записано решение.
- **126.** Цикл идёт от второй строки к последней: `i=1,...,m-1`.
- **127.** Для правой части выполняется такое же исключение, как для матрицы: $\widetilde d_i=d_i-m_i\widetilde d_{i-1}$. Поэтому используется уже **обновлённый** `result[i-1]`, а не исходное значение `rhs[i-1]`. Первый элемент остаётся $\widetilde d_0=d_0$.
- **128.** Последнее уравнение после исключения содержит только $p_{m-1}z_{m-1}=\widetilde d_{m-1}$. Деление записывает в `result[-1]` уже компоненту решения $z_{m-1}$.

## Строки 129–131. solve_tridiagonal: обратная подстановка

```python
        result[i] = (result[i]-upper[i]*result[i+1])/pivots[i]
```

- **129.** `range(len(result)-2, -1, -1)` задаёт обратный проход: старт `m-2` — предпоследняя позиция; граница `-1` не включается; шаг `-1` уменьшает индекс. Получается последовательность `m-2,m-3,...,0`. Это не обращение к элементу `result[-1]`, а параметры генератора индексов.

и использует найденный `result[1]`. В сумме прямой и обратный проходы также стоят $O(m)$.

## Строки 134–140. explicit_stability: спектральная проверка явного шага

```python
def explicit_stability(problem, n, tau, boundary):
    """Спектр полной схемы с выбранным ГУ, без неоднородных добавок."""
    lower, diagonal, upper, _ = spatial_operator(problem, n, boundary)
    matrix = np.diag(diagonal) + np.diag(lower, -1) + np.diag(upper, 1)
    eigenvalues = np.linalg.eigvals(matrix)
    radius = float(np.max(np.abs(1 + tau*eigenvalues)))
    sigma = problem.a*tau/(problem.length/n)**2
```

- **134.** Функция принимает задачу, число интервалов, фактический шаг времени `tau` и вариант ГУ; возвращает показатели устойчивости явной схемы.
- **135.** Docstring уточняет: рассматривается однородная часть схемы с уже учтённым ГУ. Известные внешние добавки не включаются в матрицу возмущений.
- **136.** Получаются три диагонали пространственного оператора. Возвращённая функция внешней добавки присваивается `_`, поскольку для этого расчёта она не нужна.
- **137.** `np.diag(diagonal)` создаёт квадратную матрицу с главной диагональю; `np.diag(lower, -1)` размещает нижнюю на одну позицию ниже главной; `np.diag(upper, 1)` — на одну выше. Их сумма — полная матрица $L$ размера `size × size`. Здесь полная матрица нужна для собственных значений, а не для прогонки.
- **138.** `np.linalg.eigvals(matrix)` вычисляет собственные значения $\lambda_j(L)$. Результат — массив; в общем случае его элементы могут быть комплексными.
- **139.** Для явного шага матрица перехода $B=I+\tau L$, поэтому её собственные значения равны $1+\tau\lambda_j$. `np.abs` берёт их модули, `np.max` — наибольший, `float` превращает скаляр NumPy в обычное число Python. `radius` — спектральный радиус $\rho(B)=\max_j|1+\tau\lambda_j|$.
- **140.** Вычисляется фактическое $\sigma=a\tau/h^2$; вместо отдельного `h` в знаменателе стоит `(length/n)**2`.

Если два решения различаются только небольшим начальным возмущением $e^0$, то
$e^{k+1}=(I+\tau L)e^k$: одинаковая внешняя добавка вычитается. Поэтому она не участвует
в этой матрице. Для затухающего собственного режима множитель должен иметь модуль не больше 1.
В исходной диссипативной задаче превышение 1 показывает рост такого режима.
Проверка спектра одной сетки не заменяет доказательство равномерной устойчивости при $h\to0$;
для несимметричных матриц возможны и переходные эффекты. Если изменение Robin-параметров
создало физически растущие моды, требование $\rho\le1$ тоже нуждается в отдельной интерпретации.

## Строки 141–144. explicit_stability: внутреннее условие и результат

```python

    # 2*sigma - c*tau <= 1. Спектр дополнительно учитывает левое ГУ.

    return sigma, radius, interior_ok
```

- **141.** Первая строка комментария ограничивает следующее достаточное условие случаем `c<=0` и говорит именно о внутренних строках, без специальной граничной строки.
- **142.** Вторая строка комментария записывает неравенство `2*sigma - c*tau <= 1` и напоминает, что влияние ГУ учтено отдельно в спектре.
- **143.** Условное выражение возвращает результат сравнения с `1+1e-12`, если `c<=0`. Небольшая добавка $10^{-12}$ допускает округление около границы. Если `c>0`, возвращается `None`, то есть эта конкретная проверка не применяется.
- **144.** Возвращаются три значения: фактическое `sigma`, спектральный радиус `radius`, логический результат `interior_ok` либо `None`.

Откуда внутреннее условие: явное обновление для внутреннего узла имеет вид

$$
u_i^{k+1}=\sigma u_{i-1}^k+(1-2\sigma+c\tau)u_i^k
+\sigma u_{i+1}^k+\tau f_i^k.
$$

При $a>0$, $\tau>0$ соседние коэффициенты неотрицательны. Чтобы центральный тоже
был неотрицателен, нужно $1-2\sigma+c\tau\ge0$, или $2\sigma-c\tau\le1$.
При $c\le0$ сумма коэффициентов равна $1+c\tau\le1$, то есть внутренний шаг
не усиливает максимум по этому достаточному условию. Это условие монотонности,
оно может быть строже точной границы спектральной устойчивости.
При $c=0$ получается известное $\sigma\le1/2$.

## Строки 173–178. solve: theta и матрица временного шага

```python
    theta = SCHEMES[scheme]
    lower, diagonal, upper, forcing = spatial_operator(problem, n, boundary)
    factors = None
    if theta:
        factors = factor_tridiagonal(-theta*tau*lower, 1-theta*tau*diagonal,
                                     -theta*tau*upper)
```

- **173.** По имени схемы из `SCHEMES` извлекается вес `theta`: 0, 1 или 0.5.
- **174.** Строятся диагонали $L$ и функция вектора $g(t)$ с выбранным способом обработки левого ГУ.
- **175.** `factors=None` означает, что факторизации пока нет. Для явной схемы она так и не понадобится.
- **176.** `if theta:` использует истинность числа: ноль считается ложью, ненулевое число — истиной. Поэтому блок выполняется для `implicit` и `cn`.
- **177.** Начинается факторизация матрицы $A=I-\theta\tau L$. Её нижняя диагональ равна `-theta*tau*lower`, главная — `1-theta*tau*diagonal`. В последнем выражении каждый элемент `theta*tau*diagonal` вычитается из 1: получается главная диагональ с единичным вкладом от матрицы $I$.
- **178.** Третий аргумент задаёт верхнюю диагональ `-theta*tau*upper`; закрывается вызов. Возвращённые данные сохраняются в `factors` один раз, до временного цикла.

Переход к общей формуле: уже имеется система $\dot v=L v+g(t)$. Приближаем производную
разностью, а правую часть — взвешенной суммой нижнего и верхнего слоёв:

$$
\frac{v^{k+1}-v^k}{\tau}
=(1-\theta)(Lv^k+g^k)+\theta(Lv^{k+1}+g^{k+1}).
$$

Переносим неизвестные верхнего слоя влево:

$$
\underbrace{(I-\theta\tau L)}_A v^{k+1}
=\underbrace{(I+(1-\theta)\tau L)v^k
+\tau((1-\theta)g^k+\theta g^{k+1})}_{\mathrm{rhs}}.
$$

| `theta` | Что получается | Что нужно вычислять |
|---|---|---|
| 0 | $v^{k+1}=v^k+\tau(Lv^k+g^k)$ | Только известный нижний слой; СЛАУ нет |
| 1 | $(I-\tau L)v^{k+1}=v^k+\tau g^{k+1}$ | Полностью неявный шаг; прогонка |
| 1/2 | $(I-\tau L/2)v^{k+1}=(I+\tau L/2)v^k+\tau(g^k+g^{k+1})/2$ | Кранка — Николсона; прогонка |

При $\theta=0$ и 1 аппроксимация времени первого порядка; при $\theta=1/2$ — второго
для достаточно гладкого решения. В `pde` та же формула применяется и к граничному ОДУ,
поэтому граничная строка тоже использует соответствующий вес времени.
Для `first`/`three` алгебраическое ГУ уже исключено из $L$ и $g$.

## Строки 190–195. solve: правая часть, прогонка и точное правое ГУ

```python
        # (I-theta*tau*L) v^{k+1} = (I+(1-theta)*tau*L)v^k
        #                                + tau*((1-theta)g^k+theta*g^{k+1}).
        rhs = old + tau*((1-theta)*apply_operator(lower, diagonal, upper, old)
                         + (1-theta)*old_forcing + theta*new_forcing)
        u[k+1, start:n] = rhs if factors is None else solve_tridiagonal(factors, rhs)
        u[k+1, n] = problem.right(t[k+1])  # точное ГУ первого рода
```

- **190.** Первая строка комментария записывает матричное уравнение временного шага. `I` в комментарии — единичная матрица; в вычислении её не создают полностью, а учитывают через диагональ.
- **191.** Продолжение комментария задаёт взвешенную внешнюю добавку. Комментарии не выполняются Python и служат пояснением двух следующих строк.
- **192.** `rhs` начинается с `old`, то есть $v^k$. `apply_operator(...)` возвращает $Lv^k$; он умножается на `1-theta` и затем на `tau`. Получается $v^k+\tau(1-\theta)Lv^k$ вместе с продолжением следующей строки.
- **193.** Добавляются `(1-theta)*old_forcing` и `theta*new_forcing`, причём общий множитель `tau` действует и на них. Закрываются скобки выражения. Результат — одномерный массив правой части длины `size`.
- **194.** Если `factors is None`, это явная схема, и новый вектор равен `rhs`. Иначе решается $Av^{k+1}=\mathrm{rhs}$ прогонкой. Результат записывается в `u[k+1,start:n]`, то есть только в неизвестные нового слоя. Условное выражение вычисляет только выбранную ветку.
- **195.** В правый край нового слоя `u[k+1,n]` записывается точно заданное `right(t[k+1])`. Комментарий указывает, что это ГУ первого рода. Это точная подстановка функции ГУ в узле, а не использование аналитического решения для внутренних точек.

На явном шаге $\theta=0$ все члены с новым временем в `rhs` умножаются на ноль:
неизвестные нового слоя действительно не входят в правую часть.
Для неявного шага $\theta=1$ исчезает явный вклад $Lv^k$, а матрица учитывает всё $Lv^{k+1}$.
Для Кранка — Николсона оба времени имеют одинаковый вес.

```python
        if boundary != "pde":
            k1, k2, g = boundary_relation(problem, h, boundary)
            u[k+1, 0] = k1*u[k+1, 1] + k2*u[k+1, 2] + g*problem.left(t[k+1])
        old_forcing = new_forcing
        if not np.all(np.isfinite(u[k+1])):
            raise FloatingPointError("Переполнение решения: уменьшите шаг по времени.")
    return x, t, u
```

- **196.** Этот блок нужен только для `first` и `three`, поскольку их $u_0$ был исключён из системы. При `pde` $u_0^{k+1}$ уже вычислен в составе вектора на строке 194.
- **197.** Получаются все три скалярных коэффициента алгебраического ГУ. Теперь третий нужен, поэтому он назван `g`, а не `_`.
- **198.** Вычисляется $u_0^{k+1}=k_1u_1^{k+1}+k_2u_2^{k+1}+g\varphi(t_{k+1})$. Все соседи берутся именно с **нового** слоя: `u[k+1,1]`, `u[k+1,2]`. Позиции 1 и 2 — физические индексы полного массива, независимо от локальной нумерации матрицы. При `first` второе слагаемое нулевое.
- **199.** `old_forcing=new_forcing` делает уже вычисленную добавку текущего нового слоя «старой» для следующей итерации. Это обычное присваивание ссылки, но далее массивы не изменяются на месте; следующая `forcing(...)` создаст новый массив.
- **200.** `np.isfinite(u[k+1])` проверяет каждый элемент нового слоя: нет ли `NaN` или бесконечностей. `np.all` требует конечности всех элементов; `not` выбирает наличие хотя бы одного плохого значения.
- **201.** Если конечность нарушена, выбрасывается `FloatingPointError`. Это защита от результата с переполнением, а не оценка точности: большое, но конечное неустойчивое решение такой проверкой не отсекается.
- **202.** Отступ уменьшается до уровня тела функции: цикл закончен. Возвращаются все координаты, все времена и вся таблица решения, включая начальный слой и обе границы.

## Строки 205–206. max_error: двумерная таблица точного решения и максимум по узлам

```python
def max_error(problem, x, t, u):
    return np.max(np.abs(u - problem.exact(x[None, :], t[:, None])), axis=1)
```

- **205.** Объявляется функция ошибки. `x` имеет форму `(n+1,)`, `t` — `(M+1,)`, `u` — `(M+1,n+1)`.
- **206.** В одной строке создаётся таблица точного решения, вычисляются модули разностей и максимум по пространству. Разберём каждую операцию в её порядке вложенности.

`x[None,:]` вставляет новую ось перед координатами: получается строка формы `(1,n+1)`.
`None` здесь используется в индексе NumPy как команда вставить ось, а не как отсутствие настройки.
Двоеточие берёт все координаты. `t[:,None]` вставляет ось после времён: получается столбец
формы `(M+1,1)`. NumPy согласует их при вычислении `exact`:
каждое время комбинируется с каждой координатой, и возникает таблица
$E_{ki}=U(x_i,t_k)$ формы `(M+1,n+1)`.

Затем `u-E` вычисляет разность соответствующих элементов, `np.abs` берёт модуль.
`np.max(...,axis=1)` убирает пространственную ось: индекс 0 осей — время, индекс 1 — пространство.
По каждой строке берётся наибольшая ошибка, включая оба граничных узла:

$$\delta_k=\max_{0\le i\le n}|u_i^k-U(x_i,t_k)|.$$

Возвращается одномерный массив длины `M+1`, то есть $\delta(t_k)$ для всех времён.
Если бы стояло `axis=0`, получилась бы другая величина — максимум по времени для каждого узла.
Без `axis` получился бы единственный максимум по всей таблице.

## Строки 229–234. convergence_study: выбор согласованных сеток

```python
def convergence_study(problem, final_time, sigma, sizes, output):
    """tau пропорционально h²; при удвоении N число шагов увеличивается в 4 раза."""
    base = sizes[0]
    if len(sizes) < 3 or base < 3 or sigma <= 0 or any(n % base for n in sizes):
        raise ValueError("Сетки сгущения должны быть целыми кратными первой.")
    base_steps = int(np.ceil(final_time*problem.a/(sigma*(problem.length/base)**2)))
```

- **229.** Функция исследует ошибку при изменении пространственного шага. `sizes` — список чисел интервалов, например `[10,20,40,80]`.
- **230.** Docstring формулирует правило: $\tau\propto h^2$. Это и обеспечивает постоянное $\sigma=a\tau/h^2$.
- **231.** `base=sizes[0]` берёт первое число интервалов как базовое. Функция предполагает непустой список; для пустого списка обращение к `[0]` вызовет ошибку ещё до следующей проверки.
- **232.** Проверяется, что есть хотя бы три сетки, базовое число интервалов не меньше 3, `sigma>0` и каждое `n` делится на `base` без остатка. `n % base` — остаток деления; нулевой остаток считается ложью, ненулевой — истиной. `any(...)` становится истинным при хотя бы одном некратном `n`. Генератор `n % base for n in sizes` вычисляет остатки по очереди.
- **233.** Если условие нарушено, выдаётся `ValueError`. Сообщение краткое; проверка включает и число сеток, и допустимость базовых параметров.
- **234.** Вычисляется базовое число шагов $M_0=\lceil Ta/(\sigma h_0^2)\rceil$, где $h_0=\ell/\texttt{base}$. Округление вверх выполняется **один раз на базовой сетке**. Фактическая базовая sigma поэтому может немного отличаться от запрошенной.

Ниже число шагов на остальных сетках будет увеличиваться в квадрате отношения размеров.
Это позволяет удержать одинаковое конечное время и строго одинаковую фактическую sigma,
вместо независимых округлений числа шагов на каждой сетке.

Математический смысл наклона: если $\varepsilon(h)\approx C h^p$, то
$\ln\varepsilon\approx\ln C+p\ln h$. Коэффициент при $\ln h$ и есть наблюдаемый порядок $p$.
Здесь исследуется совместное уменьшение $h$ и $\tau$ при $\tau\propto h^2$:
это не отдельное измерение порядка по времени. Для Эйлера $O(\tau+h^2)$ превращается
в $O(h^2)$, для Кранка — Николсона $O(\tau^2+h^2)$ также обычно определяется $h^2$.
Первое ГУ в общем случае может ограничить порядок до 1, но для точного решения
этого варианта член $hU_{xx}(0,t)/2$ равен нулю. Поэтому наклон около 2 возможен и для `first`.
Если передать несортированные `sizes`, строка 249 всё равно возьмёт последние три,
а не сама найдёт три наименьших $h$; стандартный вызов передаёт правильный возрастающий список.

## Строки 271–276. stability_experiment: малое высокочастотное возмущение

```python
def stability_experiment(problem, n, final_time, output):
    """Рост малого высокочастотного возмущения при sigma<1/2 и sigma>1/2."""
    figure, axes = plt.subplots(1, 3, figsize=(15, 4))
    x = np.linspace(0, problem.length, n+1)
    perturbation = 1e-8*np.cos((n-0.5)*np.pi*x/problem.length)
    perturbation[-1] = 0
```

- **271.** Функция ставит численный эксперимент устойчивости. `n` и `final_time` задают сетку и длительность именно этого эксперимента, `output` — папку графика.
- **272.** Docstring описывает сравнение двух значений sigma: ниже и выше стандартной границы $1/2$. Реальные критерии дополнительно учитывают $c$ и ГУ через спектр.
- **273.** Создаются три панели по числу ГУ. Здесь `sharey=True` не указан: вертикальные шкалы панелей могут подбираться независимо.
- **274.** Создаются координаты всех `n+1` пространственных узлов.
- **275.** Начальное возмущение задаётся формулой $\eta_i=10^{-8}\cos((n-\tfrac12)\pi x_i/\ell)$. `1e-8` — амплитуда $10^{-8}$; множитель частоты `n-0.5` делает колебания близкими к максимально различимой сеткой частоте. Такие колебания хорошо выявляют неустойчивость явной диффузионной схемы. Это тестовое возмущение, а не новое аналитическое решение задачи.
- **276.** Последний элемент возмущения принудительно равен нулю. По формуле косинус на правом конце и так нулевой математически, но явное присваивание убирает ошибку округления и сохраняет точное правое начальное значение.

Для непрерывного косинуса производная в нуле равна нулю. Однако это не гарантирует точного
выполнения каждого дискретного левого ГУ на начальном слое; при ненулевой `beta` меняется
и непрерывная комбинация. Эксперимент задаёт малое возмущение начальных данных,
а со следующих слоёв использует выбранную обработку ГУ. Это важно отличать от утверждения,
будто введённый косинус обязательно является точным собственным вектором каждой матрицы.

## Строки 283–288. stability_experiment: два расчёта и разность


в огромное. На неустойчивой сетке высокочастотная часть разности начинает расти.
